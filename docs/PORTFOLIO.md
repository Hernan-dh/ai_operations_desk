# Portfolio evidence

## Public experience

Publish the application together with its required n8n service, or present it through a local screen recording. It uses synthetic requests but does not simulate successful decisions when n8n is unavailable.

The Connection dialog makes the boundary explicit: both the managed route and a custom route require an n8n workflow.

## Evidence to include

Capture these three items after a successful local AI execution. Do not include API keys, user accounts, or n8n credential details.

1. **Public demo:** the landing page with an access request and the rendered case.
2. **Workflow:** the n8n canvas showing Receive request, Deterministic baseline, AI enrich request, Validate AI output, Apply deterministic policy, and Return case.
3. **Execution:** the output panel containing `engine: gemini-with-deterministic-policy-v1`, a required human review, and the audit trail.

## Suggested video script

Keep the recording under one minute:

1. Open the public-demo interface and submit the repository-access example.
2. Point out category, priority, human review, procedure, and audit trail.
3. Open the n8n execution generated by that request.
4. Point out the structured model output and the final decision engine.
5. Emphasize that the model proposes classification while the policy node controls missing information and approval.

## Suggested portfolio description

> AI Operations Desk is an auditable, n8n-orchestrated operations-triage application. Its Gemini workflow demonstrates prompt engineering, structured output, controlled procedure retrieval, deterministic human-review policy, failure handling, and containerized self-hosting.
